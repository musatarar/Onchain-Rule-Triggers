ONCHAIN RULE TRIGGERS

WORKING NAME · THE PRODUCT NAME IS UNDECIDED

Write rules about on-chain activity. The engine ingests blocks, decodes each transaction into the token transfer its calldata makes, and evaluates every enabled rule against that stored data. Every match leads back to its transaction hash, block, token and the conditions that held.

G1 · TOKEN= USDT G2 · AMOUNT> 1,000,000 MATCH

"More than 1M USDT leaves our hot wallet", as a tree you can read before you save it.

HOW A RULE IS WRITTEN

  • Type the rule as a sentence. The LLM layer proposes a condition tree of AND / OR / comparison nodes.
  • Check and edit the tree before saving. The structured builder is always available.
  • Every rule is evaluated; every rule that matched is recorded. Rules are not first-match.

WHAT IT DOES TODAY

  • EVM chains by EIP-155 id. Sample data is five Ethereum mainnet blocks.
  • Decodes transfer(address,uint256) and transferFrom(address,address,uint256) calldata.
  • Single-row comparisons within one block. Aggregates across blocks (sums, counts) are not available.

WHAT IT DOES NOT KNOW

  • Decoded transfers are unverified: nothing checks that the call succeeded.
  • A transfer on a contract the token catalog does not recognise has an unknown token.
  • Amounts are stored raw. When a token's decimals are unknown, they stay unknown; nothing guesses 18.
